# ADR 022: Connector SDK & Provider Registry

## Status
Accepted

## Context
Third-party integrations (Google Drive, Slack, Notion) require a standardized interface. We need a scalable approach to support dozens of connectors without branching business logic.

## Decision
1. We will use a **Provider Registry** (`ConnectorRegistry`). Every connector self-registers as a plugin. 
2. The `Connector` interface will mandate batch APIs: `fetch_changes(cursor)`, `fetch_documents(external_ids)`, `download(external_id)`, and `normalize(payloads)`.
3. Connectors execute in isolation within a `ConnectorContext` (which provides logger, metrics, queue).
4. `ConnectorCapabilities` will define feature flags per provider (`supports_webhooks`, `supports_incremental_sync`, etc.).

## Consequences
- Business logic is completely decoupled from connector-specific implementations.
- New connectors can be added as standalone modules.
