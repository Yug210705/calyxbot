# ADR 023: OAuth Credential Lifecycle & Encryption

## Status
Accepted

## Context
Storing raw access and refresh tokens in the database exposes the system to severe security risks if the database is compromised.

## Decision
1. We will never store raw `access_token` or `refresh_token` in plain text.
2. The `Credential` model will store `encrypted_secret`, `key_version`, and `provider_metadata`.
3. The encryption strategy and key versions can evolve independently of the database schema.
4. Token lifecycle (refreshing) will be managed transparently by the Connector SDK.

## Consequences
- Requires a robust KMS or local encryption utility.
- Prevents database leaks from exposing valid OAuth tokens.
