# ADR-013: Evidence-Driven Answers over Direct Generation

**Version:** 1.0
**Status:** Approved
**Last Updated:** 2026-06-30
**Owner:** Architecture Team
**Related Documents:**
- [Architecture Overview](../system/architecture-overview.md)

---

**Decision:** Every answer Calyx generates must cite specific memories as evidence. Calyx never generates answers from its own parametric knowledge alone.

**Context:** Enterprise customers need trustworthy answers. An LLM generating plausible-sounding text without citations is a liability — it could present hallucinations as organizational knowledge.

**Alternatives Considered:**

| Alternative | Reason Rejected |
|---|---|
| **Direct LLM generation** (no retrieval, no citations) | Unacceptable for enterprise use. No traceability, no verifiability, hallucination risk. |
| **RAG with source links** (retrieve chunks, generate answer, link to source documents) | Better, but source links to documents are insufficient. "This answer came from page 12 of a 50-page doc" doesn't tell you if the knowledge is current or verified. |
| **Search-only** (return matching documents, no synthesis) | Safe but low-value. Users must read and synthesize themselves. |

**Why Evidence-Driven:**
- Every answer is traceable — follow the citation to the memory, follow the memory to the source.
- Confidence is quantified — each piece of evidence has a confidence score. The user knows how much to trust it.
- Freshness is visible — the user sees when evidence was last verified and whether it might be stale.
- Contradictions are surfaced — when evidence conflicts, both sides are presented, not silently resolved.
- Accountability is clear — the answer cites who created and verified the knowledge.

**Trade-offs:**
- Higher latency — evidence assembly (retrieval + scoring + ranking) adds processing time compared to direct generation. Mitigated by caching frequent queries and optimizing the retrieval pipeline.
- "I don't know" is a valid answer — when no evidence exists, Calyx says so rather than guessing. This is a feature, not a bug, but users may initially find it frustrating.
- More complex answer generation — the LLM must synthesize from provided evidence, not generate freely. Prompt engineering is more constrained.

**Future Migration Path:** No migration — this is a core product principle. As the knowledge base grows, evidence assembly can be optimized (pre-computed evidence clusters, caching popular queries, incremental re-ranking).
