# ADR 029: Queue Architecture & Retry Policies

## Status
Accepted

## Context
Background processing is critical. Tying the system directly to Celery prevents migrating to Temporal or Dramatiq later.

## Decision
1. We will define a `TaskQueue` abstraction (`enqueue`, `retry`, `cancel`, `status`).
2. The interface will enforce a strict `retry_policy` (max_attempts, backoff_strategy, dead_letter_queue).
3. The queue will natively support emitting retry-aware lifecycle events (`TaskStarted`, `TaskRetried`, `TaskCompleted`, `TaskFailed`).

## Consequences
- Flexible asynchronous execution environment.
- Resilient processing out of the box.
