# ADR-014: Transparent Confidence Scoring

**Version:** 1.0
**Status:** Approved
**Last Updated:** 2026-06-30
**Owner:** Architecture Team
**Related Documents:**
- [Architecture Overview](../system/architecture-overview.md)

---

**Decision:** Every memory has a computed confidence score (0.0–1.0) based on a transparent, composable formula. The formula and its inputs are visible to users.

**Context:** Enterprise users need to know how much to trust the information they retrieve. A binary "verified / not verified" is too coarse. A black-box ML score is too opaque.

**Alternatives Considered:**

| Alternative | Reason Rejected |
|---|---|
| **No confidence scoring** | Users have no signal for reliability. All knowledge looks equally trustworthy, regardless of age or verification status. |
| **Binary status** (verified / unverified) | Too coarse. A memory verified yesterday and a memory verified two years ago both show "verified." |
| **ML-trained confidence model** | Black box. Users can't understand why a score is what it is. Difficult to debug, difficult to tune, requires training data we don't have at launch. |

**Why Transparent Formula:**
- Interpretable — users see exactly why a memory's confidence is 0.72 (e.g., "high base confidence, moderate freshness decay, no verification").
- Tunable — parameters can be adjusted per organization without retraining a model.
- Debuggable — when a score seems wrong, we can trace each factor.
- No training data required — works from day one.
- Composable — each factor (freshness, verification, corroboration, contradiction) is independent and can be improved without affecting others.

**Trade-offs:**
- The formula is a heuristic, not a learned model. It may not perfectly reflect actual knowledge reliability. Mitigated by the Learning Loop — user feedback calibrates parameters over time.
- Cold-start problem — default parameters are engineering estimates. They need real-world validation. Mitigated by labeling confidence as a beta feature initially.
- Formula complexity — five factors multiplied together can produce non-intuitive results (e.g., a heavily corroborated but old memory might score higher than expected). Mitigated by showing factor breakdowns in the UI.

**Future Migration Path:** If sufficient feedback data accumulates, a learned model can supplement (not replace) the formula — for example, adjusting the decay constants per memory type based on observed obsolescence rates. The formula structure remains; the parameters become data-driven.
