# ADR 028: Embedding Store Abstraction

## Status
Accepted

## Context
Vector databases are heavily optimized for batch operations. Abstracting them incorrectly leads to performance bottlenecks.

## Decision
1. We will define an `EmbeddingStore` abstraction.
2. It will expose batch-first APIs: `upsert()`, `batch_insert()`, `batch_delete()`.
3. The `SearchResult` schema is frozen to: `chunk_id`, `document_id`, `score`, `metadata`, `snippet`.
4. Embeddings will track `embedding_dimension`, `embedding_provider`, and `embedding_model_version` (e.g., OpenAI vs Gemini).

## Consequences
- Zero business logic coupling to `pgvector` or Pinecone.
- Bulk ingestion will be highly performant.
