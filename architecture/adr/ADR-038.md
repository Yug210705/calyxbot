# ADR-038: Document Lifecycle State Machine

**Date**: 2026-07-02
**Status**: Accepted
**Domain**: Knowledge Engine

## Context
As the Calyx platform scales, we need explicit architecture to handle document lifecycle state machine to maintain stability, scalability, and security for enterprise workloads.

## Decision
We will implement a strict 8-state machine for documents: PENDING -> FETCHED -> NORMALIZED -> CHUNKED -> EMBEDDED -> GRAPH_BUILT -> READY. FAILED transitions are also explicitly tracked. This prevents relying on missing rows to infer state.
