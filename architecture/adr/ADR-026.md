# ADR 026: Knowledge Object & Relation Registry

## Status
Accepted

## Context
An enterprise memory system stores facts, not just documents. We need a way to represent extracted entities and their relationships.

## Decision
1. The `KnowledgeObject` model will store entities with a strict `KnowledgeType` enum (`PERSON`, `COMPANY`, `PROJECT`, `TASK`, `MEETING`, `POLICY`, `DOCUMENT`, `TEAM`, `CUSTOM`).
2. The `KnowledgeRelation` model will store edges between objects using a strict RelationType registry (`WORKS_ON`, `REPORTS_TO`, `USES`, etc.).
3. Both models will track `extraction_confidence` and `verification_confidence` separately.
4. `properties` and `metadata` will be stored as JSONB.

## Consequences
- Forms the foundation of the Memory Graph.
- Allows the LLM extraction layer to populate typed entities that power reasoning.
