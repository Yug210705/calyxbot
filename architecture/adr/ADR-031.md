# ADR 031: Sync Engine & Incremental Cursors

## Status
Accepted

## Context
Different providers use different terminology for incremental syncs (tokens, timestamps, cursors).

## Decision
1. The `ConnectorState` will store a generic `cursor` string.
2. The sync engine will pass this cursor to the connector's `fetch_changes()` method.
3. `SyncJob` will track granular metrics: `documents_processed`, `chunks_generated`, `embeddings_generated`, `knowledge_objects_generated`, `estimated_remaining`, `total_documents`.

## Consequences
- A unified progress tracking UI can be built for any connector.
