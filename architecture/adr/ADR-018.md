# ADR-018: Audit Logging Strategy

**Version:** 1.0
**Status:** Approved
**Last Updated:** 2026-07-01
**Owner:** Architecture Team

---

**Decision:** We will capture detailed, immutable audit logs for all sensitive business logic mutations. Every log must include `before` and `after` state snapshots, alongside robust network and traceability metadata.

**Context:** Enterprise compliance (SOC2, HIPAA) requires strict traceability. A simple action name and resource ID are insufficient for forensic analysis. We must be able to prove exactly what changed, who changed it, and under what context.

**Implementation Details:**
- **State Snapshots:** `before` and `after` JSON fields represent the resource state explicitly.
- **Traceability:** `ip_address`, `user_agent`, and `request_id` are recorded for every audit event.
- **Immutability:** Audit log records cannot be updated or physically deleted.

**Why:**
- Satisfies enterprise compliance prerequisites immediately.
- Eases debugging by providing exact state transitions.
- The `request_id` ties the audit log back to the application logging tracing system.

**Future Considerations:** As the audit table grows, we will implement partitioning by month to ensure querying performance remains stable.
