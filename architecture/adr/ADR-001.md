# ADR-001: FastAPI as the Backend Framework

**Version:** 1.0
**Status:** Approved
**Last Updated:** 2026-06-30
**Owner:** Architecture Team
**Related Documents:**
- [Architecture Overview](../system/architecture-overview.md)

---

**Decision:** Use FastAPI (Python) as the backend framework.

**Context:** Calyx's backend serves a REST API, orchestrates business logic, manages authentication and authorization, runs knowledge extraction pipelines, and interfaces with PostgreSQL and LLM providers. We need a framework that supports async I/O (for LLM and database calls), has strong typing, auto-generates API documentation, and is productive for a small team.

**Alternatives Considered:**

| Alternative | Reason Rejected |
|---|---|
| **Django + DRF** | Heavier ORM coupling, synchronous by default, more boilerplate for API-first products. Django's strengths (admin panel, templating) are irrelevant for a headless API. |
| **Flask** | Too minimal. No built-in async, no request validation, no auto-generated docs. We'd rebuild half of FastAPI ourselves. |
| **Express/Node.js** | Would unify frontend and backend language. Rejected because Python's ML/AI ecosystem is critical for knowledge extraction, embedding generation, and future agent capabilities. |
| **Go (Gin/Echo)** | Excellent performance, but Python's ecosystem for NLP, embeddings, and LLM integration is significantly richer. Go would create friction in the AI pipeline. |

**Why FastAPI:**
- Native async/await — essential for concurrent LLM and database calls
- Pydantic-based request/response validation — type safety without manual schema writing
- Auto-generated OpenAPI docs — free API documentation
- Dependency injection system — clean architecture without a DI framework
- Python ecosystem — direct access to LangChain, sentence-transformers, tiktoken, and every major LLM SDK

**Trade-offs:**
- Python is slower than Go/Rust for CPU-bound work. Acceptable — our workload is I/O-bound (database, LLM API calls).
- Python's type system is opt-in and weaker than TypeScript's. Mitigated by strict mypy configuration and Pydantic enforcement.
- GIL limits true parallelism. Mitigated by async I/O for concurrent operations and process-based scaling via deployment platform.

**Future Migration Path:** If CPU-bound processing becomes a bottleneck (e.g., large-scale embedding generation), extract those workloads into dedicated Python workers or Rust/Go services behind a task queue. The FastAPI service layer remains the orchestrator.
